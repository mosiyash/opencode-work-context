# Execution item identity and advancement

## Goal

Introduce a backward-compatible checklist item model with stable IDs and an atomic Current-completion operation.

## Prompt

Implement the execution-ledger foundation for sequential checklist semantics.

Actions:
- Design and implement stable IDs for execution checklist items, with an explicit compatibility path for existing schema-1 string-array records and existing callers.
- Keep ordering deterministic so the first unfinished item is Current and later unfinished items are Queued.
- Expose read results with structured `current` and `queued` data while preserving the compatibility guarantees selected for existing consumers.
- Add a structured `work_context_complete_current` operation that requires the active stage session and an optimistic revision guard, atomically moves exactly the current item to Completed, and promotes the next item.
- Update tool exports, help/command mapping, protocol evidence where required, and the accepted ADR or a superseding ADR.
- Add focused unit and integration tests for legacy records, stable IDs, duplicate or reworded text, stale revisions, empty Current, exact promotion order, and atomic completion.

Constraints:
- Do not edit work-context projections directly; update package-managed command sources through the repository's supported generation/synchronization path.
- Preserve execution size bounds, active-session enforcement, transaction locking, and stable error behavior.
- Avoid an eager migration caused only by read or resume.

Completion criteria:
- Existing persisted ledgers remain readable under the documented compatibility strategy.
- New items have stable identities and all mutations use unambiguous identity where applicable.
- `complete_current` is atomic, revision-safe, exported, documented, and tested.
- Focused execution and integration tests pass.

Expected result: a compatible execution API that represents Current and Queued explicitly and can safely advance one checklist item at a time.


## Result

Implemented backward-compatible schema 2 execution items with stable IDs, additive Current and Queued read data, ID-aware duplicate and reword operations, and atomic revision-safe Current completion. Updated tool exports, protocol evidence, generated command guidance, ADR documentation, and focused unit and integration coverage. Full test suite, language check, and diff validation pass.
