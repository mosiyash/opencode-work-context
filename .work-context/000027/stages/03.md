# Sequential agent and UI contract

## Goal

Make agents and the TUI consistently work only on Current by default and clearly present queued work.

## Prompt

Integrate the sequential checklist contract across resume guidance, command instructions, TUI rendering, and public documentation using the execution API from the preceding stage.

Actions:
- Update resume payloads and `resume.instruction` to state the Current checklist item explicitly and distinguish Queued items.
- Add the normative agent instruction: work only on Current by default; do not combine Queued items into one change set unless the user explicitly asks.
- Update checklist TUI and snapshot consumers to use structured Current/Queued data and stable item IDs rather than text-derived option values.
- Update README, command protocol text, package-managed command projections through their supported source/sync flow, and any relevant examples.
- Add or update focused tests for resume instructions, payload shape, Current-only guidance, queue promotion visibility, TUI categories, stable option identity, legacy/no-ledger behavior, and generated-command synchronization.
- Run focused tests, then the full test suite and repository language check.

Constraints:
- Preserve explicit stage lifecycle semantics: checklist completion must not finish a stage.
- Keep user-facing and repository content in English.
- Do not broaden a Current item into Queued work in this stage's own change set.

Completion criteria:
- Agents receive an unambiguous Current item and a default prohibition on batching Queued items.
- TUI and resume consistently show the same Current/Queued ordering.
- Documentation and generated command artifacts are synchronized.
- Focused tests, full tests, and `npm run check:language` pass.

Expected result: the sequential execution model is visible and enforceable in agent behavior and UI, with complete regression coverage.


## Result

Stage completed.
