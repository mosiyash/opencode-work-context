# Fix resume dependency validation

## Goal

Allow archived dependencies when resuming a stage without weakening lifecycle validation.

## Prompt

Feedback source: ~/projects/mssh/mezzio.

Fix dependency validation during resume in the work-context repository.

Reported scenario:
- workspace 000012;
- stage 15 has status in_progress and was correctly handed off through handoff;
- stage 15 has depends_on: ["04"];
- stage 04 has status archived;
- resume 12 15 currently returns INVALID_STATE: Stage dependency is not completed: 04.

Required semantics:
1. An archived stage satisfies a dependency because archive preserves completed history and removes the stage from active work.
2. Resuming an already-started in_progress stage after handoff must not be blocked by a dependency with status archived.
3. Unfinished dependencies with statuses planned, in_progress, blocked, and needs_review must continue to block the first launch of a dependent stage.
4. Do not relax other lifecycle checks or change stable error codes unless necessary.
5. Do not edit generated .work-context Markdown, JSONL, INDEX, or SESSIONS projections directly.

Implementation requirements:
- Make the smallest correct change to the dependency validator.
- Inspect for a shared predicate such as isDependencySatisfied or a terminal-status policy, and use or adjust it rather than duplicating rules in individual commands.

Regression tests:
- an archived dependency permits resume;
- a completed dependency continues to permit resume;
- an active or unfinished dependency returns INVALID_STATE;
- a handed-off in_progress stage with an archived dependency successfully creates a new session and returns resume.next_action = await_confirmation;
- where practical, cover both padded and unpadded IDs without duplicating the complete test matrix.

Run the relevant tests. Report the root cause, modified files, exact resulting semantics, test results, and compatibility risks.


## Result

Stage completed.
