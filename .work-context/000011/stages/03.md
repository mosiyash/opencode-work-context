# Make lifecycle recovery reversible

## Goal

Add safe recovery paths for mistakenly archived stages and completed workspaces.

## Prompt

Implement safe recovery for accidental lifecycle operations in the work-context repository.

Context:
- `stage archive` currently accepts any stage without an active session, including planned or handed-off in-progress work.
- Archived stages cannot be restored through the public API; the existing stage reopen operation only accepts completed stages.
- `workspace finish` marks a workspace completed, but no public workspace recovery operation exists.
- Lifecycle operations must never occur automatically without an explicit user request.

Required behavior:
1. Add an explicit public operation to restore an archived stage to its prior actionable state. Decide and document the exact restored status rule; preserve stage identity, body, result, and a durable recovery history with a required reason.
2. Add an explicit public operation to reopen a completed workspace, with a required reason and durable history. It must not reopen cancelled workspaces unless an intentional, separately specified policy supports that.
3. Ensure resumed stages remain subject to existing session and dependency validation.
4. Do not weaken terminal-state rules for unrelated operations or change existing stable error codes unless necessary.
5. Expose the new operations consistently through core APIs, structured tools, command parsing/help, adapter/plugin surfaces, and documentation where applicable.
6. Add regression coverage for successful recovery, invalid source states, required reasons, preservation of result/history, identifier normalization, and inability to bypass active-session constraints.

Implementation constraints:
- Inspect existing `reopenStage`, archive, and workspace finish behavior before choosing the smallest compatible design.
- Use structured work-context operations only; never manually edit generated `.work-context` projections.
- Run relevant core, integration, TUI if affected, language, and package checks.
- Report the lifecycle semantics, compatibility considerations, files changed, and exact test results.


## Result

Stage completed.
