# Implement progressive relay investigation

## Goal

Make cross-project relay research incremental, bounded, and resumable within the same target-agent session, and enforce Planning as a non-blocking coordination surface globally.

## Prompt

Implement progressive investigation as the default project-agent-relay behavior. The first target-agent request must be deliberately narrow and time-bounded, returning a useful compact answer rather than attempting exhaustive project research. Define and enforce a structured response that includes the answer, confidence, unresolved gaps, and suggested follow-up questions. Allow the calling agent to issue focused follow-up questions by resuming the same target-agent session so previously discovered project context is reused. Add sensible limits for initial breadth and automatic continuation while preserving existing safety rules around retries and user approval.

Investigate the invalid-report and idle-timeout paths shown by relay runs. Improve report-format reliability and ensure long research does not remain silent until the idle timeout, using bounded intermediate progress or another minimal compatible mechanism.

Make the existing Planning dependency invariant a package-level contract for every project using work-context. Package-managed command guidance and the default Planning prompt must explicitly state that Planning stage 01 is a continuously available coordination surface and must never be used as a dependency of implementation, research, review, or other working stages. Add core validation that rejects attempts to make a working stage depend on Planning with a stable error, unless repository evidence establishes a required compatibility constraint that must first be reported. Do not implement this rule through workspace knowledge. Cover the global guidance and validation in tests.

Update relevant English documentation and tests. Keep backward compatibility only where required by an existing public contract. Do not edit work-context projections directly. Completion criteria: an initial relay request produces a compact useful response within its configured budget; follow-ups reuse the same target session; malformed reports and idle periods have deterministic handling; newly created working stages cannot depend on Planning; generated package guidance carries the invariant to all activated projects; and the focused test suite, language check, and diff check pass.


## Result

Implemented and verified the package-level Planning non-dependency invariant. Relay work was implemented in the separate project-agent-relay repository and is not part of this package release.
