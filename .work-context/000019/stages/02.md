# Support GitLab work item links

## Goal

Allow GitLab work-item URLs to be linked without rewriting them.

## Prompt

Implement native support for GitLab URLs in the form `/-/work_items/<iid>` in the `linkIssue` flow.

Update `src/core.js` URL parsing and `src/storage.js` persisted tracker-link validation consistently. Preserve the supplied canonical URL and existing `provider: "gitlab"`, project, and iid fields so title rendering continues to show `GL#<iid>` without a new metadata field. Keep existing GitLab issue, GitHub issue, and Jira URL behavior unchanged.

Add focused core tests that cover both GitLab issue and work-item URLs and rejection of malformed work-item paths. Update README tracker-link documentation to state both supported GitLab URL forms. Run `npm test` and `npm run check:language`.

Completion criteria: linking a valid GitLab work-item URL succeeds, persists that exact URL, accepts reload/validation, and all tests and language checks pass.


## Result

Added validated support for project-scoped GitLab work item URLs in tracker links, with persistence, documentation, and test coverage.
