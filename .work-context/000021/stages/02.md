# Implement live stage and attention indicators

## Goal

Implement live stage and attention indicators

## Prompt

Implement and publish the live stage activity and reason-specific attention indicator feature using the active workspace knowledge as the shared contract.

Implementation scope:
- Extend the existing attention/runtime controller with a separate ephemeral activity state keyed by native OpenCode session ID. Enter working only from live session.status busy or retry events. Clear working on session.status idle, session.idle, question events, permission events, and session.error. Do not persist or restore live working state, and do not infer it from canonical stage status, session.updated, unread attention, snapshot fallback, or historical session metadata.
- Aggregate activity for the sidebar by distinct native session IDs linked to active work-context session records for the visible workspace and stage. Ignore handed-off, closed, abandoned, archived, unmapped, or unknown sessions. Multiple working sessions produce one stage loader; expose a count only if it improves the compact UI without clutter.
- Render an animated braille-style loader adjacent to the existing lifecycle marker/title while any linked session is observed working. Use a single bounded animation timer shared by the stages panel, start it only while at least one visible stage is working, invalidate the reactive slot on each frame, and stop/clean it up when no activity remains or the TUI disposes. Preserve mouse handling, current-stage highlighting, status markers, wrapping, narrow layouts, and text fallback behavior. The loader must be best-effort and fail closed after startup or missed mapping.
- Replace generic sidebar ATTN labels with compact reason-specific presentation for response complete, question, permission, and error. Keep a textual reason and xN count so meaning never depends only on color or a Unicode glyph. Use terminal-safe markers consistent with the existing visual language, preserve current precedence and acknowledgement semantics, and update workspace/stage/session switcher presentation only where needed for a coherent user experience.
- Keep canonical lifecycle storage, server tools, candidate behavior, notification semantics, global attention delivery, and acknowledgement-by-event-key unchanged.

Verification and documentation:
- Add focused attention-engine/controller tests for live busy/retry/idle transitions, waiting/error clearing, restart fail-closed behavior, active-session-only aggregation, multiple sessions, deduplication, and cleanup.
- Add native sidebar and reactive host tests proving loader appearance/disappearance and animation without remount, coexistence with attention, reason-specific markers/counts, archived/unmapped exclusion, and timer disposal. Preserve Bun smoke coverage.
- Update English README/ADR documentation for the distinction between lifecycle status, observed live activity, and unread attention, including reliability limits and the visual taxonomy.
- Run focused tests, npm test, npm run test:integration, npm run test:tui, npm run check:language, npm pack --dry-run, git diff --check, and inspect the complete release diff.
- If all checks pass and no unresolved implementation decision remains, create an appropriate patch or minor version, commit only intended files, push main and the matching tag in the required order, monitor the Trusted Publishing workflow, verify the exact npm version and latest dist-tag, and report exact pinned and managed-package upgrade commands as required by AGENTS.md. Do not run npm publish locally or create an npm token.

Completion criteria: a stage row visibly animates only while a linked active session is currently observed working; waiting/completed/error states use concise reason-specific attention markers with accessible text; stale or restarted processes do not display false activity; all tests and release checks pass; and the verified release is published through GitHub Actions.


## Result

Implemented, verified, and published live stage activity plus compact reason-specific attention indicators. Runtime activity is ephemeral, race-safe, mapped only to active visible sessions, and rendered with a shared bounded braille loader. The sidebar now uses a compact signal column for complete, question, permission, and error states; workspace attention is grouped on a separate summary line while modals and switchers retain textual reasons. Fixed managed activation to pin exact package versions in both OpenCode configs after diagnosing stale unversioned cache behavior. Published and registry-verified releases through 0.6.2. Final verification passed: 247 Node tests, 19 integration tests, 87 Bun/OpenTUI smoke tests, language check, package dry run, and clean diff checks.
