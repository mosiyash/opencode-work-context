# Runtime Doctor and Protocol Attestation

## Goal

Implement delivery.doctor, runtime self-report, protocol marker/hash verification, and fail-fast major mismatch handling.

## Prompt

Implement the separate read-only `delivery.doctor` contract and runtime protocol evidence using the trust model in workspace knowledge.

File-level scope:
- Add `src/delivery-doctor.js` (and a small protocol constants/descriptor module if useful) for strict evidence collection, version negotiation, mismatch findings, repair guidance, and output validation.
- `plugin/work-context.js`, `plugin/server.js`, and `src/opencode-adapter.js`: provide a bounded loaded-plugin self-report from package-controlled module identity and manifest; support optional host-attested evidence only when supplied by an authoritative host API, otherwise report unavailable. Avoid process-global mutable evidence that can cross project/plugin instances.
- `src/tool-definitions.js` and `tools/work_context_doctor_delivery.js`: expose the read-only doctor operation; use a tool factory/closure if needed to preserve per-plugin runtime evidence while retaining current default exports and tests.
- `src/core.js`/`src/index.js`: add the core diagnostic boundary and exports.
- `commands/wc.md` and `bin/opencode-work-context.js`: define a canonical non-self-referential protocol descriptor, literal protocol major/minor/schema marker, and SHA-256 descriptor hash; project identical bytes through init, activate, and sync-command. Add `/wc delivery doctor` mapping.
- Read project-declared specs from supported OpenCode config locations and installed manifests without resolving or executing arbitrary modules.
- Extend `test/integration/plugins.test.js`, `test/installer.test.js`, and add `test/delivery-doctor.test.js`.

Doctor evidence:
- generated command marker/schema/hash;
- project-declared plugin spec(s);
- installed package manifest where safely discoverable;
- loaded plugin self-report and module origin/version;
- optional authoritative host-attested evidence or explicit unavailable state.
Evidence kinds are exactly `self_reported`, `host_attested`, and `unavailable`; declared/configured/installed observations must be clearly typed as observations and never mislabeled host-attested.

Behavior:
- Fail fast with `DELIVERY_COMMAND_PROTOCOL_MISMATCH` only when generated-command and loaded-plugin protocol majors differ.
- Return actionable findings, not errors, for minor/hash/package-version/origin/declaration/install mismatches and unavailable evidence.
- Negotiate major/minor conservatively: unknown major is incompatible; same-major minor differences are findings with declared compatibility direction, not silent equality.
- Return bounded repair guidance for pinned local and managed installations, using the exact model-specific commands from workspace knowledge and always requiring restart; never execute repairs.
- Keep the operation named/scoped `delivery.doctor` while allowing package installation/runtime evidence in its report.
- Do not return environment contents, cache file contents beyond approved manifest fields, credentials, tokens, arbitrary command output, or absolute paths unless safely normalized/redacted as evidence.

Completion criteria:
- Doctor can distinguish declared, installed, self-reported loaded, and host-attested/unavailable evidence.
- Current OpenCode behavior is represented honestly as host attestation unavailable.
- Protocol-major mismatch fails before ordinary findings; all other mismatches produce deterministic actionable findings.
- Marker/hash projection is byte-identical across all installer paths and detects stale command projections.
- Doctor performs no writes or repair execution.

Focused tests:
- matching local pinned and managed installations;
- stale command hash, same-major minor drift, package manifest drift, declared spec mismatch, origin mismatch;
- protocol-major mismatch stable error and precedence;
- absent/malformed configs/manifests, symlink/non-regular files, duplicate declarations;
- self-reported versus synthetic host-attested evidence and unavailable fallback;
- init/activate/sync-command marker/hash parity and restart/model-specific repair text;
- no filesystem mutation and no sensitive/absolute-path leakage.

Expected result: a trustworthy read-only delivery doctor with explicit evidence provenance and package-managed protocol attestation.
