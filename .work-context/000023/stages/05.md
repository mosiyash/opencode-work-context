# Explain Tool and Command Projection

## Goal

Expose delivery.explain through core, structured tools, wrappers, exports, and the package-managed slash command.

## Prompt

Expose the completed read-only explain contract through every supported package boundary without implementing doctor yet.

File-level scope:
- `src/core.js`: expose `explainDelivery` with the same structured `{ ok, data/error }` conventions as existing operations.
- `src/tool-definitions.js`: add `work_context_explain_delivery` with strict structured arguments for workspace/from/to/findings and no mutation-capable fields.
- Add `tools/work_context_explain_delivery.js` matching existing wrapper conventions.
- `src/index.js` and `package.json` exports/files: expose only what supported consumers need.
- `commands/wc.md`: add exact `/wc delivery explain <workspace> <from> <to> [findings JSON]` mapping and safety/presentation rules; refresh the checked-in `.opencode/commands/wc.md` only through the package's normal generated-source synchronization approach, never by project-specific logic.
- `bin/opencode-work-context.js`: prepare a single canonical command-projection path that init, activate, and sync-command all use; do not add doctor marker/hash logic before its implementation stage unless shared protocol constants are already available.
- Extend `test/integration/plugins.test.js`, `test/installer.test.js`, and delivery tests.

Constraints:
- The tool must remain read-only and pass findings as structured data, never shell-encoded commands or raw repository payloads.
- Preserve existing `delivery read` and `delivery mark` syntax and mappings.
- Generated command/loaders remain package-managed; no project policy belongs there.
- Tool/wrapper output must preserve stable errors, contract version, completeness, and omission of recommendations when incomplete.
- Ensure package exports and npm contents include the wrapper.

Completion criteria:
- Direct core, tool-definition, wrapper, and slash-command paths all reach the same explain implementation.
- Package install, activate, and sync-command project byte-identical command content and preserve `.opencode/work-context.md` plus existing config behavior.
- Existing command mappings and package exports remain compatible.

Focused tests:
- structured tool success and each stable validation/range/size error;
- wrapper import and package export smoke tests;
- command source equals checked-in projection;
- init/activate/sync-command update behavior and force/conflict behavior;
- no mutation/persistence after calls through the tool boundary.

Expected result: delivery.explain is available through all supported core and OpenCode surfaces, with package-managed projection behavior ready for the doctor protocol marker stage.
