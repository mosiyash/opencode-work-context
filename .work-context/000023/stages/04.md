# Conservative Slice Recommendations

## Goal

Add deterministic, policy-neutral candidate-slice recommendations only when explain evidence is complete.

## Prompt

Implement conservative candidate-slice recommendations for complete `delivery.explain` results.

File-level scope:
- Add a focused pure module such as `src/delivery-slices.js` for graph construction, grouping, confidence, rationale IDs, deterministic sorting, and recommendation validation.
- Integrate the module into `src/delivery.js` only after enrichment/redaction/completeness is finalized.
- Extend `test/delivery.test.js` or add `test/delivery-slices.test.js` for pure algorithm coverage and end-to-end omission rules.

Behavior and constraints:
- Consume only validated findings and already-bounded Git/traceability evidence. Do not inspect repository policy files, infer deployment semantics, execute remediation, or mutate candidates.
- Emit recommendations only when the overall explain result is complete. Every recommendation must include strategy `exact`, `shared_foundation`, or `integration`, confidence, bounded path/finding/rationale references, and `requires_user_decision: true`.
- Use connected evidence conservatively: exact for safely separable groups, shared_foundation only for evidenced shared prerequisites, integration for inseparable overlap. Weak or ambiguous evidence yields no recommendation rather than a guessed split.
- Candidate IDs and related stages may inform traceability but never ownership. Direct commits remain explicit and must not be assigned to a synthetic candidate.
- Recommendation ordering and confidence calculation must be deterministic and documented in code/tests. Do not include prose generated from commit subjects or path contents.
- Ensure redacted paths remain opaque in recommendation references and no internal clear path leaks.

Completion criteria:
- Pure deterministic recommendation logic has a small, auditable rule set.
- Every emitted slice satisfies the shared contract and user-decision requirement.
- All incomplete/truncated explain variants omit recommendations entirely.
- No new mutation, persistence, policy DSL, or project-specific assumptions are introduced.

Focused tests:
- independent path/finding groups produce exact slices;
- shared evidenced path/commit produces shared_foundation;
- overlapping inseparable groups produce integration;
- ambiguous/unmatched findings produce no speculative slice;
- direct commits, candidate traceability, redacted paths, deterministic order/confidence;
- every truncation flag and hard-limit boundary prevents recommendation output.

Expected result: bounded, deterministic, explicitly advisory candidate-slice recommendations integrated into complete explain responses only.
