# Fix non-Git TUI project root

## Goal

Make the Work Context sidebar read the same project-local storage as server tools when OpenCode runs in a directory without a Git worktree.

## Prompt

Fix inconsistent project-root resolution between server tools and the TUI for non-Git projects.

Read active workspace knowledge first, especially the confirmed non-Git root finding. Reproduce the reported behavior with an OpenCode-like API state where `api.state.path.worktree` is the sentinel `/` and the actual project directory is available from the location API.

Required behavior:
- The TUI must never treat the `/` sentinel as the project root when OpenCode supplies the actual project directory.
- Resolve the same effective project root used by structured server tools: use the real worktree for Git projects and fall back to the OpenCode project/directory value for non-Git projects.
- Prefer one shared normalization helper if it removes a real source of divergence without introducing a broad refactor; otherwise make the smallest consistent correction.
- Preserve startup timing, location polling, abort handling, missing-location behavior, read-only storage discovery, watcher behavior, sidebar refresh, attention, switchers, and existing Git-worktree behavior.
- Do not initialize Git, create work-context storage during discovery, or rewrite project configuration.
- Consider whether other TUI/plugin entry points independently consume `api.state.path.worktree` and correct only proven instances of the same sentinel bug.

Regression tests:
- `api.state.path.worktree === "/"` falls back to `location.data.directory`.
- If location returns a nested project object, its directory fallback remains supported.
- A real non-root worktree still wins without unnecessary location calls.
- Missing/late location data retains current polling and timeout semantics.
- End-to-end snapshot/sidebar coverage demonstrates that a workspace created under a non-Git project directory is visible to the current session rather than being read from `/.work-context`.
- Existing TUI and plugin tests remain green.

Update documentation only if the supported non-Git behavior is currently misstated. All repository content must remain in English. Never edit generated `.work-context` projections directly.

Run focused `stages-tui` and integration tests, the full relevant test suites, `npm run check:language`, and `git diff --check`. Inspect the final diff and status without altering unrelated worktree changes.

Expected result: after managed activation in an ordinary non-Git directory, creating a workspace immediately makes it visible in the sidebar after normal refresh; `git init` is no longer required as a workaround.
