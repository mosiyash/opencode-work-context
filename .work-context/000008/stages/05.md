# Accept unpadded numeric identifiers

## Goal

Accept unpadded numeric identifiers

## Prompt

Extend work-context command parsing so workspace and stage identifiers may be entered without zero padding, for example `/wc resume 8 4` resolves exactly like `/wc resume 000008 04`. Apply normalization consistently across every command that accepts explicit workspace or stage identifiers, while preserving canonical padded identifiers in storage, structured results, logs, UI, and generated commands. Review the existing one-identifier disambiguation rule where six digits mean workspace and one or two digits mean stage; define strict behavior for explicit positional arguments so shorthand remains unambiguous and does not reinterpret malformed IDs. Cover zero, negatives, decimals, signs, whitespace, leading zeros, out-of-range values, nonexistent workspaces/stages, and numeric-looking titles where relevant. Use one shared parser/normalizer rather than command-specific compatibility branches, return stable validation/not-found error codes, add regression tests for padded and unpadded forms across representative commands, and update English command documentation and examples. Do not enter or resume this stage as part of creating it.
