# Add stage session switcher

## Goal

Add stage session switcher

## Prompt

Design and implement a plugin-level stage switcher bound to `Ctrl+Alt+W`. The interaction must switch between work-context stages by opening an OpenCode session associated with the selected stage, never by rebinding or mutating the current session. Present stages for the current workspace with clear status and session availability. If the selected stage already has sessions, switch to the appropriate existing session, preferably the active or most recent resumable session according to an explicitly documented rule. If it has no session, perform the equivalent of structured `work_context_start_session` (`/wc resume <workspace> <stage>`), create the stage-bound session, and then open it. Investigate OpenCode plugin APIs for keyboard shortcuts, selectors, session creation, and session switching; handle API limitations without simulating textual slash commands when a structured operation is available. Define behavior for completed, archived, blocked, active, and planned stages; multiple sessions per stage; unsaved/in-flight work; cancellation; creation or switching failures; and shortcut conflicts. Ensure the current stage session remains intact, avoid accidental automatic continuation across stages, add regression tests for existing-session and no-session paths, update English documentation and configuration guidance, and report the final UX and any platform limitations.

## Result

Implemented and corrected the plugin-level stage session switcher. Ctrl+Alt+W and work_context.open show a searchable current-workspace selector with stage status, blockers, archived stages, and native session availability. Existing OpenCode-backed sessions are opened by deterministic active/state/recency/ordinal ranking without lifecycle mutation. For a stage with no available session, the corrected flow creates and opens a separate OpenCode session, then executes the public structured session command wc with arguments resume <workspace> <stage>; this runs the normal /wc contract and work_context_start_session in the destination session so its agent receives resume.instruction. The earlier direct-core implementation was rejected after live feedback showed that it bound stage 05 but left the destination conversation empty. The prior action browser remains work_context.actions. Added ADR-0004, README guidance, stable UI errors, and regression tests. Verification after correction: npm test passed 100 and skipped 2; npm run test:tui passed all 53 on an isolated rerun. One parallel TUI run transiently timed out in the pre-existing live-refresh frame test and passed immediately when rerun alone. Syntax and git diff checks passed. Live validation of the corrected command execution requires an OpenCode restart. The already-created stage 05/01 session needs a one-time handoff/resume recovery because it was bound by the superseded implementation before the correction.
