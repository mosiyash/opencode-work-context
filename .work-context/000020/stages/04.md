# Commit candidates atomically

## Goal

Publish a ready candidate as a commit while preserving concurrent unfinished work and the ordinary Git index.

## Prompt

Implement explicit commit publication for ready candidates. Add a repository-scoped candidate/Git lock with documented lock ordering relative to the existing work-context write lock. Under the lock, resolve the current branch HEAD, construct an alternate index from current HEAD, and apply the candidate's exact patch. If the candidate base is stale, reapply only when it is clean and semantically exact; otherwise return a concrete stale/overlap conflict without modifying refs, index, candidate, or worktree. Create the tree and commit, update the current branch ref atomically with the expected old HEAD, record the commit hash/status in local candidate metadata, and ensure the existing working tree naturally retains only unrelated WIP against the new HEAD. Never invoke interactive Git, never stage through the ordinary index, and never auto-commit from plugin hooks. Add a structured commit-candidate tool and `/wc` command/help contract with explicit candidate ID and commit message behavior. Test competing candidates, changed HEAD, overlapping hunks, detached HEAD, hooks/signing policy as explicitly supported, lock contention/recovery, ref-update races, failure rollback, and invariants that unrelated WIP and the normal index are byte-for-byte unchanged. Expected result: one ready result can be committed and shipped while other startup-mode work remains unfinished in the same branch and working tree.


## Result

Implemented atomic publication of ready commit candidates with repository-scoped Git serialization, alternate-index patch application, compare-and-swap branch updates, committed candidate metadata, stable conflict and failure errors, structured tool and `/wc` command support, and documented hook/signing behavior. Added coverage for competing and stale candidates, overlaps, detached HEAD, lock contention and release, ref races, rollback, message behavior, and byte-for-byte preservation of unrelated work and the ordinary index. Verification passed: 228 tests passed with 2 skipped, language check passed, and `git diff --check` passed.
