# Add workflow mode and sidebar indicator

## Goal

Persist standard/startup workspace mode, expose an explicit mode-changing tool, and display the active policy in the sidebar.

## Prompt

Implement the workspace workflow-mode foundation. Add optional workspace metadata `mode` with allowed values `standard` and `startup`; legacy records with no field must resolve to `standard` without being rewritten. New workspaces default to `standard`, with creation API support for an explicit mode if that fits the existing interface. Add a dedicated structured tool for changing a workspace mode and command/help syntax `workspace mode <workspace> <standard|startup>`; do not overload `storage.mode`. Include mode in workspace/stages snapshots and workspace list responses where appropriate. Render `Workflow · <mode>` directly below the workspace title in both the native sidebar slot and text fallback, preserving existing attention/status/stage behavior. Update strict metadata validation, tool exports, generated command source, tests, README/help, and the sidebar ADR contract. Keep standard mode behavior otherwise unchanged and do not manually edit generated work-context projections. Verify focused tests, the full relevant test suites, language checks, and diff hygiene. Expected result: users can explicitly switch modes, legacy workspaces remain compatible, and the current mode is always visible in the compact sidebar.


## Result

Implemented workspace workflow modes `standard` and `startup` with strict metadata validation, legacy defaulting without rewrites, explicit creation support, and the `work_context_set_workspace_mode` tool plus `/wc workspace mode` command. Added mode to workspace listings and read-only snapshots, and rendered `Workflow · <mode>` in native and text sidebars. Established `.opencode/work-context.md` as the project-owned additive instruction overlay, documented package-managed extension boundaries, and changed installer updates to preserve `.work-context/config.yaml` and merge `.opencode/tui.json` plugin entries. Updated README, ADR, command projections, exports, and regression coverage. Verification passed: npm test (213 passed, 2 skipped), npm run test:tui (82 passed), focused core/integration/installer tests (76 passed), language check, and git diff --check.
