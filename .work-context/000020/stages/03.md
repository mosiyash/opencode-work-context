# Build commit candidate capture

## Goal

Represent a ready subset of shared working-tree changes as explicit local candidate state without touching the normal Git index.

## Prompt

Implement the local commit-candidate model and safe capture/preview APIs after workflow mode support exists. Store candidate metadata and patch payloads under `.work-context/local/` only; never place candidate payloads in tracked workspace projections. Define strict schema/versioning, stable candidate IDs, workspace association, title/message, base HEAD, draft/ready/discarded status, timestamps, selected paths, and the exact captured patch. Add a Git adapter that verifies the repository and builds candidate previews with a temporary `GIT_INDEX_FILE` populated from the recorded base. Support explicit full-path capture and exact unified-patch/hunk capture; do not infer ownership from stages or session history. Reject paths outside the repository, unsafe patches, binary/unsupported cases with stable errors, and attempts to use candidates outside startup mode. Add structured create, capture, preview/show/list, ready, and discard tools plus clear `/wc` command/help mappings. Candidate operations must leave the normal index, unrelated files, and unrelated hunks unchanged. Cover legacy/no-Git behavior, deletion/rename/untracked files where supported, stale bases, malformed patches, and ordinary-index preservation in temporary Git repositories. Document the candidate lifecycle and limitations. Expected result: startup work can snapshot an explicit ready patch while unrelated WIP remains active, but no branch commit is created yet.


## Result

Implemented local startup-mode commit candidates with strict local metadata and patch storage, isolated temporary Git index capture/preview, path and unified-patch capture, stable validation errors, structured tools, /wc mappings, documentation, and regression coverage. Verification passed: npm test, TUI tests, language check, npm pack dry run, and git diff check.
