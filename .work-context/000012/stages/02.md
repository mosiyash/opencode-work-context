# Build the attention state engine

## Goal

Build the attention state engine

## Prompt

Implement the event-normalization, state, persistence, and TUI-controller foundation for background-session attention. Read active workspace knowledge before coding; it contains the agreed product contract and supported OpenCode signals.

Scope:
- Add a focused attention module under plugin/ with pure/testable state transitions keyed by native OpenCode session ID.
- Normalize session.idle, session.status, question.asked, permission.asked, session.error, and observed compatible v2 question/permission event variants without treating generic session.updated as completion.
- Track enough busy/idle state to avoid startup/replay false positives. A background busy-to-idle turn should create one attention event; question, permission, and error should create or upgrade attention with an explicit reason.
- Define stable event keys from host IDs where available and deterministic fallback fingerprints otherwise. Duplicate delivery must not create duplicate attention or notification requests.
- Model acknowledgement so opening one native session clears only the event actually observed; an older acknowledgement must not clear a newer event.
- Persist bounded local attention/deduplication state alongside existing recent-stage TUI state in .work-context/local/tui-state.json. Preserve existing data, tolerate missing/malformed files, prune stale entries, and never write canonical projections or lifecycle JSONL.
- Add the TUI lifecycle controller/subscriptions with reliable cleanup and duplicate-loader protection. Resolve foreground session dynamically from api.route.current; when identity is unavailable, retain attention rather than dropping it.
- Expose a small API that later stages can use to query/subscribe/acknowledge attention and receive a callback for newly created background attention. Do not add OS notification execution or broad UI presentation in this stage.

Tests:
- busy-to-idle, idle without prior observed work, question, permission, error, retry, event variants, priority upgrades, deduplication, foreground suppression, race-safe acknowledgement, shared native IDs, malformed persistence, restart restoration, pruning, and disposal/no duplicate subscriptions.
- Follow existing Node and Bun-compatible test patterns; do not require a desktop notification daemon.

Completion criteria:
- Pure semantics are documented by tests.
- Existing recent-stage persistence remains compatible.
- Existing server/TUI plugins and lifecycle behavior are unchanged.
- Run relevant unit/integration/TUI tests and git diff --check.
- Report exact host-event assumptions and any compatibility fallback used.
