# Deliver Linux desktop notifications

## Goal

Deliver Linux desktop notifications

## Prompt

Add safe Linux desktop delivery for newly created background attention, then document and verify the complete feature. Read active workspace knowledge and results from stages 02 and 03 first.

Scope:
- Add a small dependency-free OS notifier adapter with a portable boundary and a Linux notify-send implementation.
- Enable Linux OS notifications by default when notify-send is available. Unsupported platforms, a missing binary, DBus/desktop-session absence, timeout, nonzero exit, or spawn failure must degrade silently to the existing in-app indicator and must never break TUI startup/event processing.
- Invoke notify-send directly with fixed executable/argument arrays; never use shell interpolation, arbitrary command configuration, or untrusted executable paths.
- Sanitize and bound title/body. Include only Work Context workspace ID/title, stage ID/title, and a controlled reason such as response complete, question, permission, retry requiring attention, or error. Never include prompt/message/tool contents, paths, secrets, or raw provider errors.
- Do not implement click-to-open in this release.
- Connect delivery only to newly created background attention, not replayed/restored entries or duplicate events. Foreground events remain represented according to the attention contract but must not emit an OS notification.
- Add a minimal documented opt-out if the existing validated project config can support it cleanly; preserve strict config validation and backwards compatibility. Do not add arbitrary notifier command settings.
- Update README and any appropriate ADR/architecture documentation with behavior, Linux prerequisites, defaults, privacy, fallback, and limitations.

Tests and verification:
- Unit-test argument construction, sanitization/truncation, supported/unsupported platform handling, missing notifier, timeout/failure, default enablement, opt-out, deduplication, foreground suppression, and no notification replay after restart using injected spawn/platform functions. Never execute a real desktop notifier in automated tests.
- Run npm test, npm run test:integration, npm run test:tui, npm run check:language, npm pack --dry-run, and git diff --check.
- Manually report how to verify notify-send behavior in an installed OpenCode project.

Completion criteria:
- A linked background session needing attention produces one safe Linux desktop notification and persistent in-app attention.
- Notification infrastructure is optional, failure-isolated, and ready for later macOS/Windows adapters.
- Documentation and package contents are complete.
