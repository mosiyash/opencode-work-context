# Implement light Git commit acknowledgement

## Goal

Implement the agreed `/commited <SHA>` control-plane command without affecting shared-worktree safety.

## Prompt

Implement the approved user-acknowledged Git commit coordination feature. Read the active workspace knowledge first; it is the authoritative contract.

Required behavior:
- Add `/commited <short-or-full-SHA>` (the one-t spelling is intentional) as an explicit acknowledgement operation. The user supplies the abbreviated SHA already printed by `git commit`; never require a follow-up Git command.
- Treat it as a light control-plane operation. Do not bind it to a named model; use the developer's local light capability mapping where OpenCode supports routing. It must avoid standard/deep reasoning and avoid a second primary-agent analysis response. If direct deterministic handling is supported, prefer it.
- Capture a per-active-session Git checkpoint locally, outside tracked work-context projections and workspace knowledge. Determine the smallest compatible bootstrap point, preserve no-Git/non-Git behavior, and do not migrate old workspaces.
- On acknowledgement, resolve the input to a unique commit, require it to be current HEAD, require the previous checkpoint head to be its ancestor, require an unchanged attached ref, and reject ongoing Git operations. On success, advance only the active session checkpoint and return a compact acknowledgement.
- Do not infer ownership of commits, files, hunks, candidates, or stages. Do not change candidate lifecycle or startup candidate semantics. Preserve prohibitions on reset, revert, amend, and unknown-worktree overwrite.
- For unknown HEAD/worktree movement, use only bounded targeted checks before a planned write. Stop and ask on non-fast-forward movement, branch changes, detached HEAD, active Git operations, invalid or ambiguous SHA, a SHA not at HEAD, or unknown overlapping target-file edits. Permit disjoint changes.
- Keep standard and startup behavior compatible. Do not make sidebar snapshots read Git state or introduce tracked session/checkpoint data.
- Expose the feature through the appropriate structured tools, package-managed command/protocol artifacts, and documentation. Do not put project-specific policy in generated loaders.

Tests and verification:
- Add focused repository-fixture coverage for short and full SHA success; ambiguous/invalid/missing hashes; acknowledgement not at HEAD; branch/ref changes; rewritten/non-ancestor history; detached HEAD; active Git operation; independent local state per concurrent session; no mutation of tracked workspace projections or candidate lifecycle; and compact output/routing behavior.
- Test the command or protocol integration at the strongest boundary the host exposes. If direct light routing is not technically available, document the exact host limitation and retain model-agnostic metadata without inventing a fake guarantee.
- Run affected tests, the relevant full test suite, language check, package dry run, `git diff --check`, and inspect the working tree. Record substantive progress and verification in the canonical stage execution state.

Expected result: after a user runs `git commit`, entering `/commited f86f75a` acknowledges that exact current commit promptly using the local light tier or a direct local handler, while genuine concurrent Git risks still stop safely.


## Result

Implemented the standalone `/commited <SHA>` acknowledgement command with deterministic local per-session Git checkpoints, strict current-HEAD/ref/ancestor/Git-operation validation, stable structured errors, and no candidate or canonical lifecycle mutation. Added package-managed command installation and sync support, protocol metadata, documentation, and focused regression coverage. Verified with npm test (325 passed, 2 skipped), integration and TUI suites, language check, package dry run, and diff check.
