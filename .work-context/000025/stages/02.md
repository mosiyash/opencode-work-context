# Stage-local checklist visibility and progression

## Goal

Make stage-local execution checklists easy to inspect without persistent sidebar noise, and ensure agents visibly advance through them.

## Prompt

Implement the approved stage-local execution checklist UX and agent progression contract.

Required behavior:
- Reuse the canonical stage execution state as the only checklist store; do not introduce a parallel todo model or edit work-context projections directly.
- Extend the read-only stages snapshot with the current stage's execution state or a normalized checklist projection sufficient for the sidebar and modal. Preserve the existing read-only openExisting boundary and deterministic empty/error behavior.
- When sidebar details are enabled with the existing `<leader>d` binding, show a compact Todo summary only when execution state exists. Use the approved icon format: `Todo · ✓ 2/8 · • 3/8 · … 5 · ! 0`. Interpret the first ordered `remaining` item as current, later `remaining` items as queued, `completed` as done, and `blockers` as blockers. Omit unavailable segments rather than showing misleading state. Keep the checklist hidden when details are collapsed.
- Add a read-only modal for the current stage's complete checklist. Show current, queued, completed, blockers, and verification content with robust terminal-safe markers; use `[ ]` for queued rows rather than the unsupported square glyph. Include scope and decisions only when useful without overwhelming the task list. Handle absent workspace, absent current stage, absent execution state, narrow terminals, stale snapshots, and read errors without crashing or mutating storage.
- Register a keyboard-layout-safe shortcut using a non-letter second key. Use `<leader>2` (`Ctrl+X 2`) for the checklist modal. Do not replace or conflict with existing `<leader>t` dependency-tree behavior or other registered Work Context bindings.
- Update the `/wc` agent protocol so that after a meaningful checklist item is completed, the agent atomically moves it from `remaining` to `completed`, retains ordering, reads the latest revision before mutation, and briefly reports the transition in normal output, for example `✓ 2/8 · next • 3/8 Check the subscription`. Do not repeat the complete checklist after every tool call, and do not skip blocked work unless independence is established.
- Keep all repository artifacts in English and preserve backward compatibility for persisted schema-1 execution records. Prefer deriving the active item from ordered `remaining` over adding a new persisted status unless implementation proves that impossible.
- Add focused tests for snapshot projection, summary formatting, details visibility, modal rendering and empty/error states, shortcut registration and collision avoidance, live refresh after execution updates, and relevant generated command/protocol projections. Update user-facing documentation where the shortcut or behavior is documented.

Completion criteria:
- Existing execution records continue to load unchanged.
- `Ctrl+X D` conditionally reveals the compact approved Todo summary.
- `Ctrl+X 2` opens a read-only checklist modal for the current stage.
- Existing dependency-tree and navigation shortcuts still work.
- Agent instructions preserve and announce checklist progression without persistent output noise.
- Relevant automated tests and language checks pass, with verification results recorded in stage execution state.
