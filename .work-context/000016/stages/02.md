# Implement global activation

## Goal

Implement global activation

## Prompt

Implement global package installation with project-scoped activation for work-context. First verify, from the installed OpenCode integration/API and authoritative project evidence, the supported mechanism for registering a plugin globally and how user-level and project-level configuration are merged. Do not rely on undocumented global npm resolution from project-local bare imports.

Implement the smallest supported design where the package can be installed once globally while each project explicitly activates it. Preserve the current project-local installation path and its exact-version behavior. Add a clear project-level configuration contract with `enabled: true|false` only if it is necessary for the supported loading mechanism; ensure a project-level explicit setting overrides the global default. Do not introduce default-on global activation unless global plugin registration, local opt-out, and duplicate-instance behavior are confirmed and covered.

Prevent duplicate server tool or TUI registrations when a project has both local and global integration. Keep server-only hosts functional and preserve read-only discovery: merely loading or checking activation must never create `.work-context` data. Update English documentation with installation, activation, upgrade, precedence, local fallback, and migration examples.

Add focused tests for global activation, inactive projects, local-install fallback, explicit project overrides, duplicate prevention, package resolution, and server/TUI behavior as feasible in the repository's test harness. Run the relevant test suite plus project checks. Completion criteria: documented, tested behavior works through supported OpenCode APIs; existing local setup stays compatible; no installation path depends on machine-specific generated absolute imports. Expected result: a maintainable global-install workflow with explicit, predictable per-project activation.
