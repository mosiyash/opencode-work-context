# Durable Knowledge

## KC-0001: Current integration and global-loading options

- Kind: fact
- Status: active
- Created: 2026-11-13T07:59:17.776Z
- Updated: 2026-11-13T07:59:17.776Z
- Sources: []

The package is currently installed per project by `npx opencode-work-context init`. It installs an exact devDependency and generates `.opencode/plugins/work-context.js`, optional TUI loader files, and `.opencode/tui.json`; loaders use bare package imports. Plugin behavior is project-bound through OpenCode-provided directory/worktree and project-local `.work-context` storage. There is no global installation mode or tests for global/local precedence. Recommended direction: separate global package installation from project activation. Keep activation project-local and explicit first, with a supported config marker or loader generated by a CLI. Do not implement global default-on mode until OpenCode's global plugin discovery, per-project exclusion semantics, and duplicate-load behavior are verified. Key risks: Node cannot reliably resolve npm-global bare imports from project loaders, global and local versions may both load, package upgrades become fleet-wide behavior changes, and default-on affects unrelated projects. Need tests for activation precedence, global/local duplicate prevention, package resolution, server-only/TUI behavior, multi-project processes, and missing/malformed config.

## KC-0002: Local installation precedence

- Kind: decision
- Status: active
- Created: 2026-11-13T10:19:55.672Z
- Updated: 2026-11-13T10:19:55.672Z
- Sources: []

When both global activation and a project-local package installation are present, the project-local installation takes precedence and is the only work-context plugin instance loaded for that project. This preserves the project's pinned exact version and avoids duplicate server or TUI registrations. A globally installed copy applies only when no local installation is configured for the project.

## KC-0003: Supported managed package activation

- Kind: decision
- Status: active
- Created: 2026-11-13T10:25:45.178Z
- Updated: 2026-11-13T10:25:45.178Z
- Sources: ["https://opencode.ai/docs/plugins/","https://opencode.ai/docs/config/"]

OpenCode supports published package plugins in project `opencode.json(c)` and merges plugin arrays from applicable configuration files in precedence order. A project entry `opencode-work-context` is the supported activation mechanism; OpenCode manages package resolution and caching, so project-generated npm-global import paths are unnecessary. A later project plugin entry `-work-context` disables a globally configured plugin. The implementation adds `activate` and `deactivate`: they merge a plain JSON `.opencode/opencode.json`, install only the `/wc` command projection, do not create work-context storage or local dependency files, and refuse activation when the local generated loader exists. This preserves pinned local installation as the sole loaded integration and prevents duplicate server/TUI registrations.
