# ADR and compatibility spike

## Goal

Document the read-only modal decision and validate the smallest public TUI command, binding, and dialog contract.

## Prompt

Create a separate Proposed ADR for the fast Work Context TUI modal and Ctrl+Alt+W shortcut. Include context, decision, MVP boundaries, relationship to explicit lifecycle and canonical storage ADRs, rejection of direct custom-tool invocation and internal OpenCode APIs, alternatives, consequences, risks, and compatibility testing requirements. Add it to an ADR index if one exists. Then implement only a minimal compatibility spike, not the full modal: a separate TUI module registers command work_context.open with ctrl+alt+w through the public API if the installed runtime supports it, opens a trivial supported dialog, and closes it. Preserve the existing server export and existing stages panel behavior. Record exact runtime command results and any blocker; never use internal registries or hidden mutation. Completion criteria: ADR exists and is indexed, spike is minimal and isolated, and compatibility is honestly marked confirmed or blocked.


## Result

Created Proposed ADR-0003 documenting fast read-only Work Context modal, Ctrl+Alt+W, public TUI boundary, explicit /wc mutations, alternatives, consequences, and compatibility gate. No ADR index exists, so no index update was needed. Added isolated plugin/work-context-modal.js spike. Fake host confirmed public-shaped registerLayer command/binding, dialog open/close, and lifecycle disposal. Direct JSX without host renderer reproduced `Error: No renderer found`; spike now requires injected host runtime.jsx and safely no-ops without it. Actual interactive OpenCode loader and keyboard/dialog behavior remain unconfirmed and must be checked later; no internal APIs or mutations used.
