# General functionality fixes

## Goal

General functionality fixes

## Prompt

Investigate and fix the duplicate Stages block in the OpenCode TUI. Symptom: one OpenCode session displays two identical Stages blocks with the same workspace and stage list in the sidebar; duplication persists after a full restart. Identify the exact source of double loading or registration of the stages TUI plugin. Check the local loader at .opencode/tui-plugins/work-context-stages.js, .opencode/tui.json, the package TUI entrypoint, and the host slots.register API. Account for OpenCode 1.18.25. Do not break panel updates when sessions or work-context state change, and preserve parallel work in stage 10. Never edit .work-context Markdown, JSONL, INDEX.md, SESSIONS.md, or other projections directly. Add a regression check proving that only one panel is registered. Run npm test and, if possible, verify the real OpenCode TUI. Expected result: the sidebar displays exactly one Stages block and its data and live refresh continue to work.

## Result

Fixed duplicate Stages blocks in OpenCode TUI 1.18.25. The cause was two nested TUI loaders with different plugin IDs, so both called slots.register. The aggregate TUI entrypoint now preserves the stable work-context-stages ID, allowing OpenCode to reject the duplicate before slot registration. Added a nested-loader regression test. Verification: npm test passed 87 tests with 0 failures and 2 skipped; npm run test:tui passed 45 tests; a live OpenCode 1.18.25 run displayed exactly one Stages block with current data.
