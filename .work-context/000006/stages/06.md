# Modal navigation and filtering

## Goal

Turn the modal into a useful read-only browser for workspace, stage, and session state.

## Prompt

Continue from KC-0004 and implement the useful read-only modal UX, not another audit. Replace plugin/work-context-modal.js placeholder dialog with a native api.ui.dialog.replace(() => api.ui.Dialog(...)) modal using the host-owned runtime.jsx injected by .opencode/tui-plugins/work-context-stages.js. Use readWorkContextSnapshot from src/work-context-snapshot.js as the only modal data boundary and reuse the existing controller pattern in plugin/stages-tui.js for initial load, debounce/poll/fs.watch refresh, stale last-successful snapshot retention, and cleanup.

Required view: all workspaces, selected workspace stages, status markers, current workspace/current stage highlighting, active/current session and existing session metadata, titles/descriptions, deterministic empty state, structured error state, and visible stale/error indicator. Required interaction: safe bounded keyboard navigation, workspace/stage selection, search/filter, details view, and normal close without changing prompt/session state. Keep command work_context.open and Ctrl+Alt+W registered via public api.keymap.registerLayer; do not use api.command.register, internal OpenCode registries, tui.command.execute for tools, or any direct server custom-tool invocation.

Strict read-only constraints: no WorkContext.open, no directory/file writes, no projection edits, no lifecycle operations, no session registration, no LLM calls, no prompt insertion yet (that belongs to stage 07), and no implicit message parsing. Storage may be absent, empty, malformed, or change while reading; failures must not crash the TUI or initialize storage. Preserve server plugin and existing stages sidebar behavior. Add focused fake-host/render tests for model/view/navigation/filtering where practical, but do not execute package/integration/interactive verification commands until the developer explicitly authorizes them. Update no canonical .work-context projections manually. Before handoff, record implementation details, unverified scenarios, and risks in Knowledge.


## Result

Stage completed.
