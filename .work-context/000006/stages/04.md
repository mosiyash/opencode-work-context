# TUI modal foundation

## Goal

Add the separate TUI plugin contract, command, shortcut, minimal modal, and lifecycle cleanup.

## Prompt

Build on the confirmed public OpenCode runtime contract from the prior stage. Add a separate TUI plugin module and export, keeping opencode-work-context/plugin and opencode-work-context/server behavior unchanged. Register command work_context.open and Ctrl+Alt+W using api.keymap.registerLayer when supported; do not fall back to internal APIs. The command opens a minimal modal via public api.ui dialog/Dialog APIs and closes through the supported host mechanism. Add a project-local TUI loader/config example generated by the installer, with host Solid/JSX runtime wrapping where required. Register cleanup through api.lifecycle.onDispose and dispose command/modal registrations safely. No full workspace list, search, mutation, tool calls, prompt insertion, or implicit parsing yet. Add focused contract tests only if they do not require the prohibited full verification run. Completion criteria: package import and fake-host registration contracts are represented, server plugin remains separate, and modal open/close has an explicit public API path or a documented runtime blocker.


## Result

Added plugin/tui.js as the separate TUI aggregator, composing the existing read-only stages adapter with the new modal adapter. Updated ./tui package export to plugin/tui.js while preserving ./plugin and ./server exports. Foundation registers work_context.open through public api.keymap.registerLayer with Ctrl+Alt+W using the upstream-compatible { key, cmd, desc } binding shape, opens a minimal Dialog through api.ui.dialog.replace, closes through api.ui.dialog.clear, and disposes registration via api.lifecycle.onDispose. The loader continues injecting host-owned Solid/JSX runtime. No full modal/read model/search/mutations were added. Interactive OpenCode loading remains unverified.
